========================================================================================================
ADAPTIVE SPLIT-INFERENCE CONTROLLER
========================================================================================================
REAL      : the memory ceiling (from Llama 3.1 8B parameter counts),
            the p95 quality table (300 WikiText passages), byte costs,
            and the decision logic itself.
SIMULATED : the condition stream. Bandwidth, free RAM, battery and
            temperature are fed from a scenario rather than read from
            hardware. Reading them live needs a physical device and
            is future work.

========================================================================================================
A. QUALITY BUDGET: SET ONCE PER REQUEST, NOT ADAPTED
========================================================================================================
The budget is a property of the REQUEST, not of the session. The
application declares it when the request is submitted and it holds
for that inference - the split is chosen from it and the edge loads
layers accordingly, so it cannot change partway through.

It is a user-facing knob because per-input quality cost cannot be
predicted from the activation (tested five ways; strongest
correlation 0.446, mean held-out R2 of a learned model 0.000). The
system cannot infer how much a request matters, so the application
states it.

Three separate requests, identical device conditions:

                     request   budget                                        decision
--------------------------------------------------------------------------------------------------------
              strict request     0.05  L6  grouped(8,4,4)   208912B     33.4ms    memory
            balanced request     0.10  L4  grouped(8,4,4)   208912B     33.4ms    memory
             relaxed request     0.25  L8  grouped(4,4,4)   205562B     32.9ms    memory

  Three budgets, three different splits, two different schemes.
  Within any one request the budget is FIXED; only device conditions
  vary, which is what section B traces.

========================================================================================================
SUMMARY
========================================================================================================
  decisions evaluated : 21
  reconfigurations    : 8
  reconfiguration rate: 38%

  Without hysteresis the controller would reconfigure on every
  reading - 21 times rather than 8. Each reconfiguration means
  the edge loads or drops layer weights (416 MB per layer at bf16),
  so suppressing unchanged decisions is not cosmetic.

========================================================================================================
ACTIVE vs BINDING CONSTRAINTS
========================================================================================================
A constraint can become ACTIVE without being BINDING - it demands
something the system is already doing. The controller compares
OUTCOMES, not causes, so these produce no reconfiguration. A naive
implementation reacting to 'thermal limit crossed' would reconfigure
for nothing.

  step  8      thermal limit reached: thermal active, binding = thermal, no reconfiguration
  step 17   critical battery AND hot: thermal and battery active, binding = battery, no reconfiguration

========================================================================================================
OSCILLATION UNDER HOVERING MEMORY
========================================================================================================
Free memory bouncing either side of a layer-fit boundary, as real
devices do when background processes allocate and release.

  step 11  RAM 6.40GB  -> L6 grouped(8,4,4)
  step 12  RAM 6.55GB  -> L6 grouped(8,4,4)
  step 13  RAM 6.40GB  -> L6 grouped(8,4,4)
  step 14  RAM 6.55GB  -> L6 grouped(8,4,4)

  No thrashing: the hovering does not cross a decision boundary,
  so the configuration holds. This does NOT prove the controller
  is immune - it means these particular values fall on the same
  side of the boundary.

  LIMITATION EITHER WAY: the hysteresis acts on DECISIONS, not on
  INPUTS. It suppresses a repeat of the same answer but would not
  suppress genuine oscillation between two valid answers. A deployed
  system would need input smoothing or a dwell time before acting.

EFFECT OF PROMPT LENGTH (7.81GB / 10Mbps / strict)
========================================================================================================
Length changes the transmitted SIZE but not the scheme choice -
quality varies little with length (ratios 0.85-1.2 across a 4x
change), so one quality table covers all lengths.

  At 2000 tokens, uncompressed bf16 is 16,384,000 B and takes
  13107 ms at 10 Mbps. The controller's
  choice is about a quarter of that.
